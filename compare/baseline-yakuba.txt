# Accepted differences: yakuba-vnc (Neo4j 4.4.16) vs yakuba-vnc:v0.0 (2026.08.1)
# on neuprint-yakuba, the parallel CalVer release.
#
# Each line is matched as a plain substring against the finding text. Accepting
# a difference is a claim that you looked at it and it is intended -- so each
# entry says why, and what would make it go away.
#
#   ./compare/compare-datasets.py neuprint-yakuba yakuba-vnc yakuba-vnc:v0.0 \
#       --baseline compare/baseline-yakuba.txt
#
# ---------------------------------------------------------------------------
# WHAT EVERY ENTRY HERE ASSUMES, AND WHY THE ASSUMPTION IS WEAKER THAN IT LOOKS
# ---------------------------------------------------------------------------
#
# Every entry assumes both stores were built from the SAME segmentation and so
# differ only in build time and pipeline. compare-datasets.py enforces the part
# it can see -- a Meta.uuid mismatch ignores this whole file -- but matching
# uuids are NECESSARY, NOT SUFFICIENT.
#
# A uuid names a DVID node. An UNLOCKED node keeps being written to under that
# same name, so two builds citing one uuid read the same pointer at different
# times rather than the same data. Verified 2026-11-05: `5572acf8fd5d`, which
# the yakuba nightly pins to, is the ONLY unlocked node of ~132 in the repo.
#
#   curl -s "http://emdata7.int.janelia.org:8700/api/repo/<uuid>/info" \
#     | python3 -c "import json,sys; print(json.load(sys.stdin)['DAG']['Nodes'])"
#
# Check `Locked` before trusting a clean run. For a comparison that has to mean
# something, build both sides from a LOCKED uuid -- `22f36e70ca11` (locked
# 2026-11-04T22:42:57, the node the current head was cut from) or
# `7d0d1d848bb1` (locked 2026-10-21, the earlier v0.0 source).
#
# ---------------------------------------------------------------------------
# NOT IN THIS FILE, DELIBERATELY
# ---------------------------------------------------------------------------
#
# skeletons/skeleton and roimeshes/mesh. They failed on v0.0 only until
# 2026-10-21, because config.json's dvidkv entries declared
# "dataset": "yakuba-vnc" and so did not serve "yakuba-vnc:v0.0". Fixed by
# adding a second store per datatype with its own unique "instance" name -- the
# right answer was to fix the config, not to accept the difference. Both report
# identical as of 2026-11-05.
#
# nodes / Segment. On 2026-11-05 the CalVer store had ten MORE Segments
# (22,239,867 vs 22,239,857): real bodies, 108,608 to 1,770,040 voxels, all
# confirmed present in DVID at that uuid, each with pre = post = 0 and an empty
# roiInfo. They appeared between the nightly's 22:42 build and the CalVer
# ingest the next day, because of the unlocked node above -- not because either
# pipeline is wrong. This is NOT accepted: node counts are the check that found
# it, and blinding them would cost more than the ten bodies are worth. Build
# from a locked uuid and it goes away.
#
# property / * and types / *. Through 2026-10-20 these were accepted as
# annotation drift, because the two builds ran three hours apart and annotations
# are fetched live from DVID rather than pinned to the uuid. As of 2026-11-05
# every one of them reports identical -- type, systematicType, class,
# entryNerve, exitNerve, all 3187 distinct types, zero body-count changes.
# The entries were removed rather than left inert: a line that currently matches
# nothing still matches the NEXT real divergence, silently. Re-add them only
# with fresh evidence of a specific drift, and say which builds drifted.
#
# endpoint / dbmeta/datasets. Was accepted for differing last-mod timestamps.
# Reports identical as of 2026-11-05.
#
# endpoint / npexplorer/autapses and npexplorer/neuronmetavals. Were accepted
# as downstream of annotation drift. Both now report "same rows, DIFFERENT
# ORDER", which the tool records as a WARNING rather than a difference, so a
# baseline entry would match nothing in any case.
#
# endpoint / cached/roiconnectivity. Was a real neuPrintHTTP defect --
# `CASE meta.overviewRois WHEN NULL` stopped matching on Neo4j 5+, and yakuba
# sets no overviewRois so it relied on that fallback. Fixed in
# connectome-neuprint/neuPrintHTTP#96, MERGED 2026-10-27 and live in 1.9.8.
# Confirmed identical on 2026-11-05. The old note said to delete this line once
# a neuPrintHTTP carrying #96 was deployed; this is that deletion.

# 1. The daily cell type is random by design.
#
#    /api/cached/dailytype picks a cell type at random and returns it with its
#    exemplar's skeleton, so two calls disagree whether or not anything is
#    wrong -- including two calls to the SAME server. The tool reports it as
#    "SHAPE DIFFERS (values vary by design)" and cannot do better, since there
#    is no stable content to compare.
#
#    NOTE THE REASON CHANGED. Before 1.9.8 this line was accepting an HTTP 400
#    from `exists(n.type)`, removed in Neo4j 5 and fixed by #96. That defect is
#    gone -- the endpoint now returns data on both sides. What is left is the
#    randomness, which is not a defect and will not be fixed. This entry is
#    therefore permanent, unlike everything else that has ever been in this
#    file.
